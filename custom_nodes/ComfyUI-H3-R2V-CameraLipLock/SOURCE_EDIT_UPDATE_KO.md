# R2V 카메라 원본 편집 수정 · 2026-09-05

## 추가 수정: 선택 모델 유지 / 해상도 UI

- 사용자가 선택한 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`를 유지합니다.
- 이 모델에는 설치된 `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`를 연결합니다. 파일 헤더의 LoRA 행렬 208쌍 크기를 검사했습니다. 실제 생성 품질/완료 검증을 대신하는 검사는 아닙니다.
- 이전 기본값인 `MiniMax-H3-Ref2VA-Acc-8Step_pruned_comfy`는 현재 모델의 96행 출력층에 3072행 가중치를 교체하려 해 오류가 발생했습니다. `FL2VA-Acc-8Step_pruned_comfy`도 같은 출력층 크기 문제를 갖고 있으므로 이름만 바꿔 선택하면 해결되지 않습니다. 파일 자체는 수정하거나 삭제하지 않았습니다.
- 기존 카메라 워크플로우에서 위 FL2VA 모델과 해당 Acc LoRA 조합이 확인되면 재시작/새로고침 후 Turbo 8step LoRA로 선택을 보정합니다. 사용자 구간/스텝/베이스 모델 선택은 유지합니다.
- 타임라인에 원본 비율 유지, 표준 종횡비 13개, Custom 직접 입력과 0.1–4.0 MP를 추가했습니다. 너비/높이를 32배수로 반올림하여 실제 MP와 함께 표시합니다. 16:9·0.5MP는 928×544입니다. 기존 사용자 표의 960×544와는 반올림 계산 방식이 다릅니다.
- 비율을 바꾸면 중앙 크롭하며 인물을 늘려 찌그러뜨리지 않습니다. 높은 MP는 처리 시간/VRAM을 크게 늘릴 수 있습니다. 배지는 경고만 하며 성능/호환을 보장하지 않습니다.
- 1MP를 넘는 출력에서는 코어의 참조 캔버스 제한과 출력 초기 잠재 데이터 해상도를 분리합니다. 코어는 수정하지 않습니다.
- 새 입력은 끝에 추가하여 기존 입력/출력 순서를 유지했습니다. 적용하려면 **ComfyUI 재시작 후 Ctrl+F5**가 필요합니다.

아래 초기 안내의 Ref2VA-Acc 기본 선택은 위 수정으로 대체되었습니다.

## 사용

ComfyUI를 재시작하고 브라우저에서 강력 새로고침한 후 `workflows/H3_R2V_Camera_SourceEdit_8Step.json`을 여세요. 예전 워크플로우를 그대로 열면 새 연결이 적용되지 않습니다.

1. 타임라인의 Upload Source Video에서 오디오가 포함된 영상을 선택합니다.
2. 업로드 시 영상 전체가 3개 구간으로 나뉩니다. 각 구간은 15초 이하, 최소 5프레임이어야 합니다. 이 워크플로우는 3분기 전용이며 구간 수를 늘리려면 생성 분기도 추가해야 합니다.
3. Segment 버튼과 플레이헤드로 구간, 카메라 구도와 이동을 정합니다. 변경 강도는 실제 샘플러 denoise에 연결됩니다.
4. R2V `MiniMax-H3-Ref2VA-Acc-8Step_pruned_comfy.safetensors`, 강도 1.0, Steps 8이 초기값입니다. 다른 LoRA를 고를 수 있지만 해당 모델에 맞는 스텝 설정은 별도 확인해야 합니다.
5. Sage ON, Spectrum OFF로 원본 유지 여부부터 확인합니다. Spectrum은 별도 ON/OFF 가능합니다. 켰을 때 설치된 Spectrum의 기본 설정을 사용하되 video blend만 0.35입니다. 성능/품질은 실제 영상으로 확인해야 합니다.
6. ComfyUI 실행 버튼으로 생성합니다. 영상·오디오 연결은 이미 되어 있습니다. 원본 변경 강도 0.35는 검증된 최적값이 아니라 보수적인 테스트 시작값입니다.

## 실제 수정

- 자동 증가 입력 이름 불일치를 피하고 설치된 H3 코어에 영상과 짝이 맞는 오디오를 명시적으로 전달합니다.
- 참조가 실제 조건에 들어갔는지 검사하고, 비어 있으면 생성하지 않고 오류로 알립니다.
- 빈 잠재 데이터 대신 원본 영상·오디오의 VAE 잠재 데이터에서 편집을 시작합니다.
- 24fps로 읽고 H3의 17n+5 규격은 마지막 프레임을 임시 반복해 맞춥니다. 출력에서는 이 패딩을 제거합니다.
- 최종 오디오는 선택된 원본 구간을 순서대로 이어 붙입니다. 원본 전체 오디오를 잘못 붙이지 않습니다. 파형은 유지되지만 저장 코덱에 따라 인코딩은 발생할 수 있습니다.
- 같은 이름의 새 업로드는 고유 파일명으로 저장하여 기존 파일 캐시 재사용을 방지합니다. 업로드 실패 시 이전 영상으로 생성되지 않습니다.
- Sage와 Spectrum은 켜진 경우에만 모델 패치를 호출합니다. 누락된 노드는 조용히 무시하지 않고 명확히 오류를 표시합니다.

## 한계와 검증 범위

원본 오디오 재사용과 샘플러 초기값 연결은 구현했지만 입술 랜드마크 추적, 3D 카메라 재투영, 완벽한 동일 인물/입모양 고정은 구현되지 않았습니다. 카메라 이동을 크게 요구하면 원본과 달라질 수 있으며 변경 강도를 낮추면 구도 변화가 작을 수 있습니다. 기존 Lip Lock 숫자는 실제 강제 제어가 아니어서 내부 UI에서 비활성화했습니다.

설치된 H3 코어를 사용한 CPU 테스트에서 참조 전달, 원본 잠재 데이터, 패딩 제거, 오디오 샘플 보존을 검사했습니다. 실제 VAE/CLIP 가중치와 생성 모델을 올려 비교한 것은 아닙니다. 기존 에셋은 삭제된 상태여서 새 영상의 시각적/입모양 비교가 남아 있습니다.

이 파일은 단일 노드 내부 샘플러가 아닙니다. 타임라인 UI와 연결된 생성 분기 3개로 구성되어 있으며 분기는 접힌 상태로 남아 있습니다. 메인 올인원팩은 수정하지 않았습니다.

## 설치 대상

다른 PC에 적용할 때는 반드시 **본인이 사용하는 ComfyUI 폴더**의 `custom_nodes/ComfyUI-H3-R2V-CameraLipLock`에 설치하세요. 코드와 UI 및 워크플로우를 함께 갱신해야 합니다.

ComfyUI/PyTorch/CUDA/드라이버를 이 업데이트로 변경하지 않습니다. 기존 VideoHelperSuite, H3 지원 ComfyUI, KJNodes H3 Sage 패치(ON 시), Spectrum(ON 시), 그리고 본인 모델/LoRA가 필요합니다. 모델 파일은 포함하지 않습니다.
